# BayesFracX User Guide

This guide provides the detailed reference for using BayesFracX. Installation of the BayesFracX Python package, a quick-start example, and experimental input paths are provided in the repository [README](../README.md). Section 7 gives the reference settings and instructions for reproducing the validation and sensitivity analyses.

## 1. Input requirements

BayesFracX takes as input a pre-segmented three-dimensional binary fracture volume.

In the current implementation:

```text
0       = fracture voxel
nonzero = non-fracture voxel
```

Segmentation of grayscale CT data is outside the scope of BayesFracX.

Supported inputs are:

- a three-dimensional TIFF file (`.tif` or `.tiff`),
- a directory containing TIFF slices,
- a RAW binary volume (`.raw`).

For TIFF input:

```python
bfx.load_volume("data/example.tif")
```

For RAW input:

```python
bfx.load_volume(
    "data/example.raw",
    shape=(nz, ny, nx),
    dtype="uint8",
)
```

RAW volume shapes are specified in NumPy order `(Z, Y, X)`. The dtype defaults to `uint8`. Supply the actual dtype when it differs. TIFF slice directories are loaded in natural filename order (for example, slice 2 before slice 10), and all slices must have the same dimensions.

Inputs must use isotropic voxels. If the supplied mask encodes fractures as nonzero values, convert it to the required zero-valued fracture convention before loading.

The BayesFracX object is initialized as:

```python
from bfx import BAYESFRACX

bfx = BAYESFRACX(
    job_name="results_example",
    voxel_size=0.05,
    seed=0,
)
```

`job_name` defines the output directory. `voxel_size` is the isotropic voxel size $\Delta$. `seed` controls point-cloud sampling, stochastic initialization of the DP-BGMM, and subsampling for visualization. For a different seed, construct a new object with the desired `seed` value. The internal stage-specific seeds are derived during initialization.

Coordinates use zero-based array indices. Array order `(Z, Y, X)` is converted to point-coordinate order `(X, Y, Z)`. The code does not apply an external spatial origin or georeferencing transform. Physical output units follow the unit chosen for `voxel_size` (see Section 4.7).

## 2. Workflow and internal state

A complete analysis follows:

```python
bfx.load_volume(...)
bfx.build_fracture_mask()
bfx.build_point_cloud()
bfx.subsample()
bfx.detect_fractures()
bfx.reconstruct()
bfx.characterize()
bfx.summary()
bfx.save()
```

The methods should be executed in this order because each stage uses the state generated by the preceding stage.

### 2.1 `load_volume()`

Loads the pre-segmented volume into:

```python
bfx.volume
```

For TIFF data, array dimensions are read from the file. For RAW data, `shape` is required and `dtype` must match the stored data. Its default is `uint8`.

### 2.2 `build_fracture_mask()`

Constructs the retained fracture voxel domain from voxels with value `0`.

Three-dimensional connected-component labeling is applied using the selected neighborhood. Components smaller than `min_component_voxels` are removed before fracture detection.

The retained fracture domain is stored as:

```python
bfx.fracture_mask
```

After constructing the mask, `bfx.volume` is released and set to `None`.

### 2.3 `build_point_cloud()`

Converts retained fracture voxels into Cartesian point coordinates.

The complete fracture point cloud is stored as:

```python
bfx.full_points
```

Coordinates are stored in `(X, Y, Z)` order in voxel coordinates, without multiplication by `voxel_size`.

### 2.4 `subsample()`

Randomly samples the complete fracture point cloud according to `sampling_percent`.

The sampled point cloud is stored as:

```python
bfx.sampled_points
```

Subsampling is applied only during fracture detection. The retained full-resolution fracture domain is preserved for reconstruction.

### 2.5 `detect_fractures()`

Applies DP-BGMM candidate clustering and iterative geometric acceptance to the sampled fracture point cloud.

For each candidate cluster, BayesFracX calculates the planarity index:

```math
P = \frac{\lambda_2-\lambda_3}{\lambda_2}
  = 1-\frac{\lambda_3}{\lambda_2}.
```

where $\lambda_1 \geq \lambda_2 \geq \lambda_3$ are the squared singular values of the centered candidate point cloud.

A candidate is accepted as an individual fracture when both:

- $P$ is greater than or equal to the current threshold in `planarity_thresholds`, and
- the number of sampled points is greater than or equal to `min_cluster_points`.

Accepted points are removed from the active point cloud and the remaining points are re-clustered. This process is repeated up to `max_rounds` within each planarity tier. A tier stops when fewer than `min_cluster_points` active points remain.

Accepted fracture elements are stored in:

```python
bfx.fractures
```

Each accepted fracture record contains its sampled point set, detection tier, clustering round, and sampled planarity.

Points remaining after all detection tiers are stored in:

```python
bfx.rejected_points
```

### 2.6 `reconstruct()`

Reconstructs each accepted fracture element within the full-resolution fracture domain.

A Euclidean distance field is calculated and stored as:

```python
bfx.distance_field
```

Accepted fracture point sets are used as individual markers. The rejected sampled points are used as a competing marker. Marker-controlled watershed segmentation is then applied within the retained fracture domain.

The distance field is calculated on the retained fracture mask in voxel units. Voxels assigned to the competing rejected marker are excluded from the reconstructed fracture elements. `bfx.rejected_points` continues to contain the rejected sampled points. It is not replaced by the full-resolution rejected region.

The reconstructed voxel set is stored as:

```python
fracture["full_points"]
```

Full-resolution planarity is stored as:

```python
fracture["full_planarity"]
```

The quality-control state is stored as:

```python
fracture["flagged"]
```

A fracture is flagged when:

```text
full_planarity < min_full_planarity
```

Flagging does not remove the element automatically. It identifies a reconstructed fracture that falls below the prescribed full-resolution planarity quality-control threshold.

### 2.7 `characterize()`

Calculates the reduced representation of each reconstructed fracture.

Each characterized fracture record is augmented with:

```text
center
normal
dip
dip_direction
polygon
area
equivalent_radius
aperture
```

#### Center

The fracture center is the centroid of the full-resolution fracture voxel coordinates. It is stored in voxel coordinates. CSV export converts it to physical coordinates.

#### Orientation

Singular value decomposition is applied to the reconstructed fracture coordinates centered at the fracture centroid.

The first two principal directions span the best-fit fracture plane and the third defines the unit normal.

The coordinate convention is:

```text
X = East
Y = North
Z = Up
```

The normal is oriented so that its Z component is nonnegative. Dip ranges from 0 to 90 degrees, and dip direction is measured clockwise from North. These are conventions for the input coordinate frame. Experimental scans must be oriented appropriately for geological interpretation. Dip direction is undefined for a perfectly horizontal plane, even if the computation returns a numerical value.

#### Boundary

The reconstructed fracture coordinates are projected onto the best-fit plane. A two-dimensional convex hull defines the fracture boundary and is mapped back to three dimensions to form the polygon.

#### Area

Projected coordinates, expressed in voxel units, are rounded to the nearest integer in the two in-plane directions. Each occupied cell represents an area of $\Delta^2$. The reported area is the occupied-cell count multiplied by $\Delta^2$. It is not the area enclosed by the convex hull.

#### Equivalent radius

The area-equivalent radius is:

```math
r_{\mathrm{eq}}
=
\sqrt{\frac{A}{\pi}}.
```

#### Spatial aperture field

The local geometric aperture is derived from the three-dimensional Euclidean distance field using the same in-plane cells used for the area calculation. For each occupied cell, the implementation takes the maximum EDT distance among the reconstructed voxels assigned to that cell:

$$
b = 2\Delta\max(d),
$$

where $d$ is the EDT distance in voxel units and $\Delta$ is `voxel_size`. If a cell contains exactly one reconstructed voxel and its maximum EDT distance is approximately one (`np.isclose(d, 1.0)`), the single-voxel correction assigns $b=\Delta$.

The field is stored on integer in-plane grid locations inside the convex-hull polygon. Locations without reconstructed fracture voxels receive zero aperture. The `aperture` dictionary contains:

| Key | Contents |
|---|---|
| `coords_2d` | In-plane grid coordinates relative to the fracture center, in voxel units. |
| `coords_3d` | Corresponding global `(X, Y, Z)` coordinates on the best-fit plane, in voxel coordinates. |
| `values` | Aperture at each stored grid location, in the length unit of `voxel_size`. |
| `mean` | Arithmetic mean of strictly positive entries in `values`. |
| `std` | Population standard deviation of strictly positive entries in `values` (`ddof=0`). |

Zero-aperture locations remain in the spatial field but are excluded from its mean and standard deviation. If no positive values exist, both statistics are set to zero.

## 3. User-defined parameters

The principal parameters are stored in:

```python
bfx.params
```

The current defaults are listed below. Set overrides before running the stage that uses them. These defaults differ from some article reference cases. Use the corresponding example driver or Section 7 for reproduction.

| Parameter | Symbol | Default | Description |
|---|---|---:|---|
| `min_component_voxels` | $N_{\min}$ | `500` | Minimum retained connected-component size in voxels. |
| `connectivity` | — | `26` | Connected-component neighborhood. |
| `sampling_percent` | $100 f_s$ | `2` | Percentage of fracture points retained for detection. |
| `planarity_thresholds` | $P_{\min}^{(t)}$ | `[0.90, 0.85]` | Planarity acceptance thresholds for successive tiers. |
| `min_cluster_points` | $N_{\mathrm{cl}}$ | `80` | Minimum sampled points required for cluster acceptance. |
| `max_components` | $K$ | `10` | Maximum DP-BGMM components available during one fit. |
| `alpha` | $\alpha$ | `1.0` | Dirichlet-process concentration parameter. |
| `max_rounds` | — | `10` | Maximum clustering rounds per planarity tier. |
| `max_iter` | — | `200` | Maximum DP-BGMM iterations per fit. |
| `n_init` | — | `3` | Independent DP-BGMM initializations per fit. |
| `min_full_planarity` | $P_{\mathrm{QC}}$ | `0.80` | Full-resolution planarity quality-control threshold. |

Example:

```python
bfx.params["sampling_percent"]["value"] = 10
bfx.params["planarity_thresholds"]["value"] = [0.99, 0.95]
bfx.params["min_cluster_points"]["value"] = 30
bfx.params["max_components"]["value"] = 15
```

Use:

```python
bfx.print_params()
```

to display the current parameter values.

### 3.1 `min_component_voxels`

Controls removal of small connected fracture components before point-cloud generation.

Increasing this value removes more small connected components from the retained fracture domain. Setting it to `0` disables component-size filtering.

### 3.2 `connectivity`

Controls the neighborhood used during three-dimensional connected-component labeling.

The article uses 26-neighbor connectivity. This parameter applies to connected-component filtering.

### 3.3 `sampling_percent`

Controls the fraction of retained fracture voxels used during detection.

Increasing `sampling_percent` increases the number of sampled points supplied to the DP-BGMM and generally increases clustering cost.

Use a percentage in `(0, 100]`. `100` retains the complete point cloud. Sampling does not change the full-resolution domain used during reconstruction.

### 3.4 `planarity_thresholds`

Defines the sequence of planarity acceptance thresholds.

Higher values require candidate clusters to be more planar. Thresholds are applied sequentially so that strongly planar elements can be accepted before less planar candidates.

### 3.5 `min_cluster_points`

Defines the minimum number of sampled points required for candidate-cluster acceptance. It also controls the stopping condition when fewer than this number of active points remain.

### 3.6 `max_components`

Defines the DP-BGMM truncation level $K$, which is the maximum number of mixture components available during one fit.

It does not prescribe the final number of extracted fracture elements.

### 3.7 `alpha`

Defines the Dirichlet-process concentration parameter.

### 3.8 `max_rounds`

Defines the maximum number of clustering and acceptance rounds performed within one planarity tier.

### 3.9 `max_iter`

Defines the maximum number of variational iterations for each DP-BGMM fit.

### 3.10 `n_init`

Defines the number of independent DP-BGMM initializations performed for each fit.

### 3.11 `min_full_planarity`

Defines the full-resolution planarity quality-control threshold.

A reconstructed fracture below this threshold is flagged for inspection.

## 4. Generated outputs

### 4.1 `summary()`

```python
bfx.summary()
```

prints a summary of the extracted fracture population and rejected sampled points. Fractures below the full-resolution planarity quality-control threshold are identified as `FLAGGED`.

### 4.2 `save()`

```python
bfx.save()
```

writes the principal saved outputs to the `job_name` directory:

```text
fractures.npz
summary.csv
```

Existing files with these names are overwritten. Use a distinct `job_name` for each run when retaining multiple results.

### 4.3 `fractures.npz`

The reloadable checkpoint contains:

- fracture records,
- rejected sampled points,
- sampled fracture point cloud,
- voxel size.

Restore saved results into a new object with:

```python
from bfx import BAYESFRACX

bfx = BAYESFRACX(job_name="results_reloaded", seed=0)
bfx.load("path/to/fractures.npz")
bfx.summary()
```

`load()` restores the saved voxel size along with the fracture records and sampled points. The checkpoint supports inspection, plotting, and export of saved results. It does not store the original volume, retained mask, complete pre-detection point cloud, EDT array, parameter dictionary, or original seed. Keep the driver and run settings to reproduce the analysis. Rerunning reconstruction or characterization requires reloading and processing the input volume.

### 4.4 `summary.csv`

The summary file contains one row per reconstructed and characterized fracture. Fractures below the full-resolution planarity quality-control threshold are retained with `flagged=1`; unflagged fractures have `flagged=0`. Fracture IDs follow their one-based record order in `bfx.fractures`.

Aperture statistics exclude zero values, as described in Section 2.7. CSV quantities are rounded for display. Use the checkpoint arrays and properties when greater numerical precision is needed.

The current columns are:

```text
id
tier
round
n_sampled_points
n_voxels
sampled_planarity
full_planarity
flagged
dip_deg
dip_direction_deg
area
equivalent_radius
aperture_mean
aperture_std
center_x
center_y
center_z
```

### 4.5 STL surfaces

Individual reconstructed fractures can be exported as triangulated STL surfaces:

```python
bfx.to_stl()
```

This generates:

```text
fracture_<id>.stl
```

for each reconstructed fracture. These meshes represent the boundary of each voxel volume, generated by marching cubes.

### 4.6 Visualization

Available visualization methods include:

```python
bfx.plot_points()
bfx.plot_fractures(use_full=False)
bfx.plot_fractures(use_full=True)
bfx.plot_polygons()
```

These provide inspection of the available input point clouds, detected sampled fracture elements, reconstructed full-resolution fracture elements, and reduced planar representations with spatial aperture.

Plot windows are interactive. Close each window to continue the driver. Comment out `bfx.plot_*()` calls for unattended runs. Visualization may subsample displayed points, without changing the stored analysis results. Plot coordinates remain in voxel coordinates, while aperture colors use the length unit of `voxel_size`.

### 4.7 Output units

Let `L` denote the length unit chosen for `voxel_size`, for example millimeters.

| Quantity | Coordinate convention or unit |
|---|---|
| `full_points`, `sampled_points`, `rejected_points`, and fracture point arrays | Voxel coordinates, `(X, Y, Z)`. |
| Stored `center` and `polygon` | Voxel coordinates, `(X, Y, Z)`. |
| `aperture["coords_2d"]` | Local in-plane voxel coordinates relative to the fracture center. |
| `aperture["coords_3d"]` | Global voxel coordinates, `(X, Y, Z)`. |
| `distance_field` | Distance in voxel units. |
| CSV `center_x`, `center_y`, `center_z` | `L`. Stored center multiplied by `voxel_size`. |
| STL vertex coordinates | `L`. |
| Aperture values, mean, and standard deviation | `L`. |
| `equivalent_radius` | `L`. |
| `area` | `L²`. |
| `dip`, `dip_direction` and their CSV counterparts | Degrees. |
| `normal`, planarity indices | Dimensionless. |

For example, `voxel_size=0.05` with a millimeter convention gives aperture and radius in millimeters, area in square millimeters, and CSV centers and STL coordinates in millimeters. Stored coordinate arrays remain in voxel coordinates.

## 5. Expected behavior and interpretation

### 5.1 Rejected points

`rejected_points` are sampled fracture points that do not satisfy the acceptance criteria after all detection tiers.

They are retained and used as a competing marker during full-resolution watershed reconstruction.

### 5.2 Flagged fractures

A reconstructed element is flagged when its full-resolution planarity falls below `min_full_planarity`.

A flag indicates that the reconstructed geometry requires inspection. It does not automatically remove the element.

### 5.3 Tortuous fractures

BayesFracX extracts locally planar fracture elements.

A tortuous physical fracture can therefore require several elements, each with its own position, orientation, boundary, size, and spatial aperture field.

### 5.4 Parameter dependence

BayesFracX is training-free but parameter-dependent.

The exact fracture partition can vary with the selected detection parameters and random seed. In particular, changes in planarity acceptance and the DP-BGMM component limit can change the granularity of the extracted representation.

### 5.5 Geometric aperture

The reported aperture field is a geometric aperture or local-thickness measurement derived from the Euclidean distance field.

It should not automatically be interpreted as hydraulic aperture or permeability.

### 5.6 Segmentation dependence

BayesFracX operates on the supplied pre-segmented fracture volume.

Segmentation uncertainty therefore propagates through detection, reconstruction, and characterization. Fractures that are not resolved or segmented in the input cannot be recovered by BayesFracX.

## 6. Computational considerations

DP-BGMM fracture detection is performed on the sampled point cloud rather than on every fracture voxel.

Detection cost therefore depends strongly on the number of sampled fracture points.

Full-resolution Euclidean distance transform and watershed operations use arrays with the input-volume dimensions. Their memory requirements therefore depend on the full grid, including non-fracture locations. Lowering `sampling_percent` reduces detection work but does not shrink these arrays.

For large CT volumes, account for the mask, distance field, marker and label arrays, point clouds, and clustering working memory. A GPU is not required for computation. The tested operating system, CPU, and RAM are documented in the [README](../README.md#tested-computing-environment). These describe a tested setup rather than established minimum requirements.

## 7. Reproducible examples

Executable drivers are provided in `examples/` for the two synthetic validation cases and the five experimental CT applications. Run them from the repository root. The [README](../README.md#experimental-ct-applications) lists the experimental input paths, volume dimensions, voxel sizes, and commands, including `examples/driver_DPM205.py`.

### 7.1 Synthetic reference cases

The synthetic inputs are `data/synthetic_3fractures.tif` and `data/synthetic_15fractures.tif`. Their drivers use the following settings:

| Parameter | Three-fracture case | Fifteen-fracture case |
|---|---:|---:|
| `voxel_size` | `1.0` | `1.0` |
| Constructor `seed` | `0` | `0` |
| `min_component_voxels` | `500` | `500` |
| `connectivity` | `26` | `26` |
| `sampling_percent` | `100` | `10` |
| `planarity_thresholds` | `[0.99]` | `[0.99]` |
| `min_cluster_points` | `80` | `30` |
| `max_components` | `3` | `15` |
| `alpha` | `1.0` | `1.0` |
| `max_rounds` | `10` | `10` |
| `max_iter` | `200` | `200` |`
| `n_init` | `3` | `3` |
| `min_full_planarity` | `0.80` | `0.95` |

The manuscript reports three and fifteen extracted fractures, respectively, with zero rejected sampled points. These are reference outcomes for the stated setup. Changing parameters or seeds can change the partition.

### 7.2 Parameter sensitivity

Use `examples/driver_synthetic_15fractures.py` as the reference. Make a copy in `examples/`, choose a distinct `job_name`, and change one parameter at a time according to the table. Reset all other settings to Section 7.1 before each run.

| Parameter | Reference | Additional values tested in the manuscript |
|---|---|---|
| `max_components` | `15` | `10`, `20` |
| `alpha` | `1.0` | `0.1`, `10` |
| `planarity_thresholds` | `[0.99]` | `[0.90]`, `[0.95]` in separate runs |
| `min_cluster_points` | `30` | `300`, `1000` |

For example, replace the existing `max_components` assignment with:

```python
bfx.params["max_components"]["value"] = 20
```

Keep `sampling_percent=10` and constructor `seed=0`. For the planarity variations, use a single-element list for each run. `[0.90, 0.95]` would instead define two sequential tiers.

To measure detection time, replace the driver's single `bfx.detect_fractures()` call with:

```python
from time import perf_counter

start = perf_counter()
bfx.detect_fractures()
detection_seconds = perf_counter() - start

n_rejected = len(bfx.rejected_points)
rejected_percent = 100.0 * n_rejected / len(bfx.sampled_points)
print(f"Extracted fractures: {len(bfx.fractures)}")
print(f"Rejected sampled points: {n_rejected} ({rejected_percent:.2f}%)")
print(f"Detection time: {detection_seconds:.3f} s")
```

This times detection only. Loading, plotting, reconstruction, characterization, and export are outside the timed interval. Retain the run settings and printed metrics alongside each output directory. The checkpoint does not save them.

### 7.3 Stochastic stability

Repeat the fifteen-fracture reference case with constructor `seed=0`, `seed=100`, and `seed=300`. Initialize a fresh `BAYESFRACX` object for each run, keeping all other settings fixed. Changing `bfx.seed` after initialization does not regenerate its internal stage-specific seeds.

The manuscript reports 15 clusters for seeds 0 and 300, and 16 clusters for seed 100, with zero rejected sampled points in all three runs. The additional cluster at seed 100 is a split of one prescribed fracture into two nearly coplanar elements. Compare orientations and geometry when matching elements across runs, because fracture IDs follow detection order.

### 7.4 Subsampling efficiency

Repeat the fifteen-fracture reference case with `sampling_percent=5`, `10`, and `15`, retaining constructor `seed=0` and all other reference parameters. The reported outcomes are:

| Sampling (%) | Sampled points | Extracted clusters | Rejected sampled points | Rejected (%) |
|---|---:|---:|---:|---:|
| 5 | 121,858 | 16 | 0 | 0.00 |
| 10 | 243,716 | 15 | 0 | 0.00 |
| 15 | 365,574 | 16 | 3,657 | 1.00 |
